# Effect plugins

Effect packages use API 1: a `wasm32-unknown-unknown` module exports `memory`,
`set_param(i32, f64)` and `render(f64, i32, i32) -> i32`. Render returns the byte
offset of packed RGB pixels. Parameter order is the catalog order; up to 16
finite values are accepted. The surface is at most 128 by 64 and is sampled onto
the daemon canvas. Existing package metadata and saved effect selections remain
compatible. Unknown API versions, imports (including WASI), start functions,
invalid frame pointers and out-of-range parameters fail closed.

## Isolation and protocol

The installed daemon starts its own executable with `--effect-worker`, before
logging, state, hardware discovery or API startup. Standalone development tools
use the sibling `freergb-effect-worker` binary. No separate installer payload is
required. Commands launch directly without a shell, and Windows workers have no
visible console. The native interpreter is trusted code running with the same
OS identity as the daemon; this is a WASM sandbox in a separate process, not an
AppContainer/seccomp boundary against a compromised interpreter.

The guest has no host imports, filesystem, network, hardware or capture access.
The interpreter limits packages to 512 KiB, memory to 8 MiB, one memory/table,
1024 table elements and two million fuel units per frame. Compilation and first
frame run in the child, including during installation. JSON-line IPC has API 1,
strict fields, monotonic request IDs, one outstanding request and a 768 KiB
message limit. Load uses a three-second deadline and render uses 250 ms,
including write/flush/read. Wrong IDs/versions, invalid JSON, oversized replies,
EOF and timeouts fault the child. Shutdown kills and reaps it, waiting at most
one second after termination. OS process creation itself is outside the deadline.

## Installation and trust

The existing marketplace and collection install actions retain their hash,
size, cancellation and immutable-version checks. Official remote catalogs now
require `catalog.sig`: hex Ed25519 signature over
`b"freeRGB effect catalog v1\0" + exact_catalog_bytes` (the final domain byte
is NUL, not a literal backslash). Public release keys are in
`crates/freergb-effect-host/keys/release-keys.txt`; the existing owner-held release
key is trusted with this distinct effect domain. Module-domain signatures are
rejected. No private key is supplied or generated by this implementation.

The compiled catalog/packages are trusted as part of the application build.
Remote signatures authenticate catalog hashes; package SHA-256 and size are
checked before validation and activation. A signed catalog proof is retained
with each remotely installed version and checked again on activation/reload,
so changing local metadata and its hash cannot bypass signature checks. The
cached remote catalog retains its signature and monotonic sequence check.
Legacy unsigned official cache files are ignored in favor of the compiled
catalog. Unsigned official releases cannot refresh; publishing the signed effect
catalog remains an owner release step.

The explicit startup `--effect-dev-directory` remains an unsigned local fixture
mode. It never enables community network requests and cannot be configured via
RPC. Only use it for locally trusted development data. Installed file changes in
this mode still need matching metadata hashes and valid guest contracts.

## Reload, enable and removal

A background monitor checks verified package files every 500 ms. A changed module
starts in a new child and must render its first frame successfully. The render
thread continues using the old child while that happens, then swaps at a frame
boundary. Invalid edits report an operation error while preserving the healthy
effect. The previous child is retained for rollback if a replacement traps on a
later frame. Parameters are retained and revalidated against changed metadata.
Published versions remain immutable; select a newly installed version to upgrade.
Live editing an existing version is intended for the explicit development mode.

`marketplace.enable` and `marketplace.disable` accept `{ "id": "aurora" }`.
Disabled IDs persist in `disabled.json`; `marketplace.status` includes
`packages.disabled`. Enable makes an installation selectable again; it does not
activate it automatically. The marketplace offers Enable/Disable controls.
`marketplace.uninstall` now also accepts the active package. Disable/removal
invalidates a live selection at the next frame and restores the previous daemon
effect. A runtime fault does the same when no healthy child rollback is available.
With no previous effect, the daemon uses black. The fallback selection is saved
through existing state persistence and the runtime error remains visible until
a successful selection. Files are retained after uninstall as before, but cannot
be loaded until reinstalled. No daemon restart is needed.

## Verification

`cargo test -p freergb-effect-host --features effect-fixture --locked` includes real
child processes for malformed/slow/crashing peers, no-read pipes, bad IDs/versions,
oversized replies, guest fuel/traps, async-context activation, signature tampering,
domain separation, reload while rendering, rejected reload, rollback after a later
trap, persistent disable and active removal. `effect-fixture` only builds a
synthetic peer binary for tests; it is not part of normal release builds. Default
workspace tests include guest/reload/lifecycle tests and daemon fallback tests.
Tests use temporary files and synthetic guests, with no hardware writes.

## Owner acceptance steps

1. Produce a release `catalog.sig` with the owner-held key and the exact effect
   domain above, publish it beside the catalog and WASM assets, then confirm a
   fresh official marketplace refresh/install succeeds. Confirm altered catalog,
   signature and package bytes are rejected. Do not share the private key.
2. With virtual devices and an isolated state directory, select a built-in effect,
   activate an installed effect, then disable/uninstall it. Confirm selection,
   frame output, persistent enabled state and visible error/fallback after restart.
3. With the explicit local development source, edit a selected WASM plus matching
   metadata hash while rendering. Confirm animation continues during preparation,
   valid replacement appears, malformed edits preserve the old effect and a
   later trapping replacement rolls back.
4. Confirm normal packaged daemon self-hosting on the owner's release build.
   Real LED output and interactive GUI acceptance remain unverified here.
