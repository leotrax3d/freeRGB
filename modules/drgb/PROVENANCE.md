The detector/device tables generated by the branch version were audited and found
correct; no generator script existed on the branch and none was required yet because
the protocol path is not ported. A generator must be added before any supported claim.

## Audit result

The 33 detector rows (DeepRGB V3/V4/V5, AG-DRGB, NEEDMAX, JPU, YICO families) and the
33 device entries (channels, LEDs per channel, protocol version) match
`DRGBControllerDetect.cpp` and `DRGBDevices.cpp` byte-for-byte. No Direct-mode path is
fully ported, so `identify()` reports no device as supported.

| Upstream item | Audit finding |
|---|---|
| `DRGBController.cpp :: SendPacket` (V4) / `RGBController_DRGB.cpp:143-168` | first packet capacity is `DRGB_V4_ONE_PACKAGE_SIZE` (316), Rust used 340; `LowCount` is a 60/84 remainder scheme, Rust sent `min(len,340)` |
| `DRGBController.cpp :: SendPacketFS` (V1/V3) / `RGBController_DRGB.cpp:172-264` | packet accounting is `led_index.div_ceil(21)` (`DRGB_V3_PACKAGE_SIZE`), Rust used 63; commit marker must be `Array + 92 + i` (0xA3) / `0x64 + 100 + i` (0xC8), Rust used 0xA2/0xC4; the 64-byte header packet must carry the leading report-id zero |
| `RGBController_DRGB.cpp:203-231` (V2) | `ArrayData[3] = 0xBB` with payload at `[4+i]` (usb_buf byte 5); branch code overwrote 0xBB and shifted the payload one byte left |
| `DRGBController.cpp:40-44, 248-262` | 500 ms keepalive (`0x65` re-send) that sustains colors is not ported |
| `RGBController_DRGB.cpp:81` | default zone size is 0 until the user configures zones; branch pre-lit all LEDs |
| `DRGBController.cpp:96-158` | upstream LED/zone naming ("Strimer ATX1", "LCD n", "Channel A1..") not ported |
