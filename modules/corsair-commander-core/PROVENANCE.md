# Provenance

Upstream: OpenRGB, https://gitlab.com/CalcProgrammer1/OpenRGB,
Commit `bbc77470a7cba56af60989e54ba910d5ac66a3ac`.
License of every used upstream file: GPL-2.0-or-later (SPDX headers verified across
`Controllers/CorsairCommanderCoreController`).

The detector table is generated by `scripts/openrgb/port-corsair-commander-core-devices.mjs`
(7 detector rows with usage page 0xFF42 and usage 0x01 on interface 0, exactly as
`REGISTER_HID_DETECTOR_IPU` in `CorsairCommanderCoreControllerDetect.cpp`).

## Audit result

All 7 detectors are inventoried but no protocol path is ported. The audited branch
version sent a fabricated 97-byte packet (`[channel, 0x22, RGB...]`, up to 31 LEDs per
zone) that does not exist in the upstream driver; it was removed.

| Upstream file/function | Notes for a future port |
|---|---|
| `CorsairCommanderCoreController.cpp :: SendCommand` | framing `00 08 <command[2]> <data>` with packet-size negotiation (V1 1025 / V2 97 / V3 65 / XT 385) and response reads |
| `CorsairCommanderCoreController.cpp :: InitController` | firmware version query `02 13`, packet size selection for Core v1 |
| `CorsairCommanderCoreController.cpp :: SetFanMode` | `1E 00 / 0D 00` write (15 bytes), Core vs XT differences, wake `01 03` |
| `CorsairCommanderCoreController.cpp :: SetLedAmount` | `1D 00 / 0C 00` write, per-zone LED counts |
| `CorsairCommanderCoreController.cpp :: WriteData` | endpoint open `0D 00`, data write `06 00` (packet_size-10 per packet) / continue `07 00`, endpoint close `05 01` |
| `CorsairCommanderCoreController.cpp :: SetDirectColor` | 699-byte RGB buffer, fixed layout with 34-LED padding per RGB-port zone after zone 0 |
| `RGBController_CorsairCommanderCore.cpp :: SetupZones` | 7 zones: AIO zone (24-LED matrix or up to 204 depending on device config read) + 6 RGB ports of 34 LEDs; LED counts are config-driven |
