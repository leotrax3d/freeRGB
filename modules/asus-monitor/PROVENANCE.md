## Behavior transfer

| Upstream file/function | Rust file/function | Behavior transferred |
|---|---|---|
| `AsusMonitorController.cpp :: GetNumberOfLEDs` | `report.rs :: query` + `lib.rs :: initialize` | 65-byte query `EC B0`, LED count from response byte 32 |
| `AsusMonitorController.cpp :: SendInit` | `report.rs :: init` | 65-byte packet `EC 35`, byte 5 = 0xFF, byte 8 = 0x01 |
| `AsusMonitorController.cpp :: SetDirect` | `report.rs :: direct` | 65-byte packet `EC 40 84`, count at byte 4, RGB bytes from byte 5 |
| `RGBController_AsusMonitor.cpp :: SetupZones` | `lib.rs :: initialize` | Single linear zone sized to the reported LED count, no fallback |
| `RGBController_AsusMonitor.cpp :: DeviceUpdateLEDs` | `lib.rs :: frame` | All colors in one `SetDirect` packet |
| `AsusMonitorControllerDetect.cpp` | `devices_table.rs / table.rs` | All 7 `REGISTER_HID_DETECTOR_IPU` rows (interface 1, usage page 0xFF72, usage 0x00A1; light bar on interface 2) |

## Changes

* Direct mode only; brightness/effect controls are not exposed by the module API.
* Upstream sends no init sequence besides the LED-count query; the device is not
  usable without a response, so a missing or zero count fails closed (the first
  branch version silently fell back to 1 LED).
* Audit corrections over the first branch version: interface/usage-page matching
  added, generator script added.
