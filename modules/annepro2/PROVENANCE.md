## Behavior transfer

| Upstream file/function | Rust file/function | Behavior transferred |
|---|---|---|
| `AnnePro2Controller.cpp :: SendDirect` | `report.rs :: direct` | 5 packets of 64 bytes: service data `7B 10 41`, packet index `(count<<4)+p`, payload length `len+4`, static message `00 00 7D`, command info `20 03 FF` + `02`, 51 payload bytes per full packet, 6 for the last (210-byte real frame) |
| `RGBController_AnnePro2.cpp :: DeviceUpdateLEDs` | `lib.rs :: frame` | Real frame layout: LED colors written at their real index; indices 40/41/52/53/60 consume one extra zero triplet, 55/56 consume two (LED_REAL_COUNT 70 = 5*14, LED_COUNT 61) |
| `RGBController_AnnePro2.cpp :: SetupZones` | `lib.rs :: initialize` | 5x14 matrix with the upstream `led_names[]` key labels (KEY_EN_ESCAPE ... KEY_EN_RIGHT_CONTROL) |
| `AnnePro2ControllerDetect.cpp` | `devices_table.rs / table.rs` | All 5 `_I` rows on interface 1 (fifth row VID 0x3311) |

## Changes

* Direct mode only; hardware effect modes and profile controls are not exposed by
  the module API; upstream sends no init/exit packets.
* The upstream last-packet data loop reads past the 210-byte frame; the module pads
  the tail with zeros (the firmware only consumes the announced payload length).
* Audit corrections over the first branch version: real-index frame layout with the
  nine gap triplets (was a dense sequential color stream), upstream LED key names,
  interface matching, generator script added.
