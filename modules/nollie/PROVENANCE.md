## Behavior transfer

| Upstream file/function | Rust file/function | Behavior transferred |
|---|---|---|
| `NollieController.cpp :: SendPacketFS` | `report.rs :: fixed` | 65-byte packets, byte 1 = packet + channel * interval (2/6/30/25 by PID), RGB or GRB byte order per PID (NOLLIE8/NOLLIE1/NOLLIE8_OS2_1/NOLLIE1_OS2_1/PRISM8_OS2_1 are GRB) |
| `NollieController.cpp :: SendUpdate` | `report.rs :: update` | 65-byte packet with byte 1 = 0xFF |
| `NollieController.cpp :: SendPacket` | `report.rs :: high_speed` | 1025-byte packets, byte 1 = channel, byte 2 = flag (1 on channel 15, 2 on channel 31), GRB data from byte 5 (device path not enabled, see below) |
| `NollieController.cpp :: SetChannelLEDs` | `lib.rs :: frame` | fixed devices: 21-LED chunks per channel then SendUpdate |
| `RGBController_Nollie.cpp :: DeviceUpdateLEDs` (fixed branch) | `lib.rs :: frame` | per zone in channel order, empty channels skipped, SendUpdate always sent |
| `NollieController.cpp :: GetChannelName` | `lib.rs :: channel_name` | Channel / ATX / GPU / EXT naming |
| `NollieControllerDetect.cpp` + `NollieDevices.cpp/.h` | `devices_table.rs / table.rs` | All 16 detectors (incl. REGISTER_HID_DETECTOR_I interface 0/2) and channels/leds/protocol per device |

## Changes

* Direct mode only; no zone-configure flow, so SetMos and InitChLEDs (upstream
  DeviceConfigureZone, only for manually resized zones) are not sent.
* Default zone LED count is the upstream per-channel maximum instead of 0.
* Audit corrections over the first branch version: GRB swap added for PID 0x2A01,
  interface matching for the three interface-2 detectors, high-speed devices no
  longer claimed, upstream channel naming ported, generator script added.
